# Dify 1.16.1 Full Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the Azure Container Apps deployment to Dify 1.16.1 with classic Agent and Agent v2 available together, Agent v2 enabled by default, and all existing timeout values preserved.

**Architecture:** Retain the existing classic Dify services and managed Azure data services. Add the Agent backend, local Agent sandbox, and a dedicated Agent SSRF proxy as internal Container Apps, with generated Key Vault credentials and an environment-controlled UI feature flag. Repair the inherited Nginx and Squid parity gaps and validate the deployment through configuration regression tests plus Terraform validation.

**Tech Stack:** Terraform/HCL, Azure Container Apps, Azure Key Vault, Azure Files, PostgreSQL Flexible Server, Azure Cache for Redis, Python standard-library `unittest`, Nginx, Squid.

## Global Constraints

- Dify API and web images are exactly `1.16.1`.
- Dify Agent backend and local sandbox images are exactly `1.16.1`.
- Plugin daemon remains `0.6.3-local`; classic sandbox remains `0.2.15`.
- Classic Agent and Agent v2 resources coexist.
- `enable-dify-agent-v2` defaults to `true`.
- Preserve `PYTHON_ENV_INIT_TIMEOUT=120`, `PLUGIN_MAX_EXECUTION_TIMEOUT=600`, `WORKER_TIMEOUT=15`, `FILES_ACCESS_TIMEOUT=300`, `PLUGIN_DAEMON_TIMEOUT=600.0`, `TEXT_GENERATION_TIMEOUT_MS=60000`, `WORKFLOW_MAX_EXECUTION_TIME=1200`, `ACCESS_TOKEN_EXPIRE_MINUTES=60`, `REFRESH_TOKEN_EXPIRE_DAYS=30`, and `SQLALCHEMY_POOL_RECYCLE=3600`.
- Internal Agent services must not have public ingress.
- Do not apply Terraform or create Azure resources.

http_access allow dst_dify_api path_files
http_access deny to_private_networks
